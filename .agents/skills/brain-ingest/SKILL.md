# Capture project knowledge

Read `brain/schema.md` and the existing index before writing. Apply the note structure to new material and preserve existing human authorship.

- Capture one useful finding per research note with a precise local page or external URL and access date. Distinguish source facts, project choices, and unresolved risks.
- Put unprocessed material in `brain/inbox/`, reference findings in `brain/resources/`, and active SRS or session records in `brain/projects/youtube-mcp/`.
- Link related notes with `[[wikilinks]]`, add requirement IDs, and record real issue/PR links when available. Do not invent references.
- Update `brain/index.md` and append the actual operation and result to `brain/log.md`.
- For significant AI work, record the goal, outcome, what worked, what failed, and verification. Attribute AI-authored notes to Codex, not to a team member.
- Keep changes local until the authorized GitHub workflow is used. Do not label a local edit reviewed, submitted, or merged.
