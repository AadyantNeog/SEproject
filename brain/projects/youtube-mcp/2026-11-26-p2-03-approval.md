## Goal

Implement P2-03's native approval boundary on the latest `origin/main`, bind an
internal one-use grant to an exact account, proposal version/digest and
operation ID, and test refusal/failure paths without operating a confirmation
control.

## Outcome

Added a Tk helper launched as a subprocess by the server, a challenge-checked
approval service and a thread-safe process-local grant store. The complete A2-06
preview is displayed in a read-only scrollable control. A close action returns
rejection; unavailable UI, helper launch/protocol failure, expiry, cancellation
and stale or mismatched helper responses fail closed. Grant consumption checks
all bindings under a lock and succeeds once. Grant loss on process restart
requires fresh approval. P2-04's atomic write claim remains a required
integration point; this task adds no write path.

## What worked

- Existing contracts and A2-06 renderer were reused without changing proposal
  schemas.
- Synthetic tests cover grant binding and replay, rejection/close, expiry,
  forged/stale challenge/operation/digest/timestamp responses, helper failure,
  and the fixture stdio server's preview resources.
- Focused WSL Python 3.13.18 run: `12 passed`.

## What failed and was corrected

The first focused run found that grant contracts are dataclasses (not Pydantic
models), so consumption now uses `dataclasses.replace`. The fake Tk scrollbar
also needed its `set` method. The corrected focused run passed.
